# ExeBuilderStudio Project Structure

This project separates the user interface from build-job preparation and external tool operations.

```text
ExeBuilderStudio-main/
├── main.py                         # Stable application launcher
├── app/
│   ├── translations.py             # English, Thai, and Shan UI text
│   ├── core/
│   │   └── backend.py              # Shared validation and legacy build helpers
│   ├── services/
│   │   ├── java_builder.py         # Java JAR-to-EXE job preparation
│   │   ├── python_builder.py       # PyInstaller job preparation
│   │   ├── installer_builder.py    # Inno Setup job preparation
│   │   └── tool_downloads.py       # Tool discovery and download operations
│   └── ui/
│       ├── main_window.py          # UI, user interaction, and process orchestration
│       ├── theme.py                # Shared visual styling
│       └── download_ui.py          # Tool download UI components
├── assets/                         # Logo, application icon, and fonts
├── installer/                      # Inno Setup project files
├── tests/                          # Unit tests for build preparation and downloads
└── docs/                           # Project documentation
```

## Responsibilities

- `main.py` remains the stable launcher so existing launch scripts can continue to call it.
- `app/ui/main_window.py` creates widgets, validates user interaction, starts `QProcess`, displays logs, and orchestrates native installer builds. Detailed build scripts are generated by platform-specific services.
- `app/services/java_builder.py` validates Java build inputs, prepares the release folder, bundles an optional JRE and adjacent `lib` folder, and returns a Launch4j process job.
- `app/services/python_builder.py` validates Python build inputs and returns a PyInstaller process job, including data folders and hidden imports.
- `app/services/installer_builder.py` validates release inputs, generates the Inno Setup script through the shared backend helper, and returns the compiler job.
- `app/core/backend.py` contains shared validation and compatibility helpers. Existing root-level imports are kept as compatibility shims to avoid breaking scripts and tests.

## Comment style

Python comments use `#`, not `//`. Keep comments focused on why a step exists, validation rules, file filtering, and platform-specific build behavior. Avoid comments that simply repeat the next line of code.

## Validation

Run `python -m compileall -q .` to check Python syntax. Run `python -m unittest discover -s tests -v` in an environment with the dependencies in `requirements.txt`; GUI tests require PySide6, and real EXE/installer builds require Windows and the relevant external tools.

## macOS distribution packaging

- `macos/build_macos_distribution.sh`: builds the native ExeBuilderStudio `.app` and `.dmg` locally on a Mac.
- `macos/README.md` and `macos/README_TH.md`: packaging instructions, optional bundled JDK, and target-tool requirements.
- `Build_Mac_App.command`: convenience launcher for macOS packaging.
